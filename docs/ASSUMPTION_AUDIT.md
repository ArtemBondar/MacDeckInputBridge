# Assumption audit (issue #31)

Scope: repository at the start of this audit, including Swift, the receiver,
packaging and CI. This is an inventory of findings, not a claim that issue #31
is complete. Owners are the maintainers of the named component; separate
behavior changes need separate reviewable PRs. Device checks remain open until
recorded on a physical Mac and Steam Deck.

| Finding and evidence | Decision and owner / follow-up | Tests and remaining validation |
| --- | --- | --- |
| Mac source-change polling (`LayoutSynchronizationState` in `SenderController.swift`) | **Keep as a safety bound.** Immediate read plus five backoffs totaling 385 ms observe the TIS identifier; time alone never confirms a switch. Exhaustion warns and retains the last sent layout. Owner: sender; existing implementation. | State tests cover changed, stale, superseded and timeout observations. Confirm rapid switches and timeout feedback on macOS. |
| Connection retry (`ConnectionRetryPolicy`) | **Keep as a safety bound.** At most eight attempts, 0.5 seconds apart, with a two-second handshake deadline per attempt; established sessions fail closed. Owner: sender. | Retry/state tests exist; verify receiver startup and Wi-Fi loss on devices. |
| Clipboard polling (`startClipboardMonitoring`, 0.5 seconds) | **Replace** if macOS offers a suitable supported change notification; otherwise name and document polling as an explicit responsiveness/battery policy. Owner: sender; separate PR. | Clipboard change state tests exist, but timer lifecycle and device responsiveness need verification. |
| Receiver handshake (five seconds, at most four pending), framing (4096 bytes), clipboard (65536 bytes; 3840-byte chunks), and read polling (200 ms) | **Keep as safety bounds.** These limit unauthenticated work, allocation, frame size and shutdown latency; malformed/oversize data is rejected and sessions release keys. The handshake uses an absolute deadline rather than a per-read timeout that trickled bytes could extend. Pending slots are released when authentication completes, rather than when an authenticated session ends. Idle reads remain open; an incomplete frame is limited to five seconds while polling for shutdown, then disconnects and releases keys. Owner: protocol/receiver; fixes in separate commits on this branch. | Protocol, framing and session tests cover several boundaries; independently inventory missing limit, timeout, saturation and shutdown integration tests before closing #31. Verify disconnect with held modifiers on hardware. |
| Receiver idle accept sleep (200 ms), qdbus child poll (10 ms), and UI child stop poll (25 ms, two-second graceful deadline) | **Replace** polling with readiness/exit notification where practical, preserving bounded shutdown; otherwise name, justify and test the bounds. Owner: receiver; separate PRs for listener and process lifecycle. | Existing tests do not establish every timeout or forced-stop path; exercise keyboard release on Deck. |
| qdbus output pipes could fill before the child exited, making a successful query time out | **Replace** with bounded concurrent pipe draining and a one-second deadline. Output above 1 MiB per stream fails safely and the child is reaped. Owner: receiver; separate commit on this branch. | Tests exercise output larger than a pipe buffer, the size bound and child timeout. Verify actual Plasma diagnostics on Deck. |
| qdbus search accepts any regular file, including an unexecutable earlier candidate | **Replace** with effective-user executable check, continuing to the next candidate; missing usable tools return an actionable diagnostic. Owner: receiver; this branch. | Unit test exercises non-executable, later executable, directory and no usable candidate. Confirm actual qdbus/Plasma integration on Deck. Executability does not prove a binary is compatible or the session bus is healthy; invocation errors remain actionable. |
| qdbus fallback paths and XKB rules in `/usr` | **Configure** discovery where alternate locations exist; runtime Plasma layout query is preferred over XKB files, and `MAC_DECK_QDBUS`/PATH already allow tool overrides. Owner: receiver; separate investigation/PR for XKB data and overrides. | Runtime list, missing match and ambiguity tests exist. Check stock SteamOS and alternate installations; no current evidence covers every layout source. |
| Layout mapping uses source name aliases, qdbus list parsing, and zero-based `u8` manual indices | **Replace** heuristic names/order where a reliable runtime identifier is available; retain validated manual overrides and fail unchanged on ambiguity. Owner: receiver; separate PR. | Matching, ambiguous and manual override tests exist. Verify custom, localized and reordered layouts on physical Deck and Mac. |
| Gamescope detection in receiver and GUI (`gaming_session`, `controller_navigation_enabled_from_environment`) | **Replace** Steam application IDs with session indicators and observed controller events. Steam IDs can also be set by Desktop Mode shortcuts; the receiver and GUI no longer use them to classify the session. Owner: receiver UI; this branch, separate commit. Session environment values can still be absent or misleading; investigate a reliable compositor capability signal separately. | Automated session and focus tests exist, but actual Desktop/Gaming event paths and shortcut launches need hardware validation. |
| UI window sizes, fixed focus order, stick thresholds, layout/scroll behavior | **Keep as safety bounds** only where they protect visibility or avoid controller jitter; **replace** static assumptions with observed geometry and controls where possible. Owner: UI; separate PR. | Focus/mapping tests exercise logic; verify mouse/touch scrolling, OSK and all controls at constrained sizes and 1280×800 Gaming Mode on Deck. |
| Steam Deck installer paths and refresh commands | **Configure** destinations through existing `MAC_DECK_INSTALL_*` overrides, discover cache tools and warn on failures. Owner: packaging; existing implementation. | Installer test uses isolated fake profile; verify actual installed source and release artifacts, launcher/icon refresh and uninstall on Deck. |
| Swift app bundle and release target/platform names | **Keep as platform contract** for the macOS and SteamOS artifacts, but **replace** path or architecture assumptions where a supported platform discovery mechanism exists. Owner: packaging; separate PR. | CI covers build paths, not every stock-device environment. Validate both installed artifacts and release assets on target devices. |

No typed content, pairing secret, or clipboard data should be included in audit
logs or diagnostics. Document new findings and add a named owner/PR as work is
split; do not close #31 while the open investigations and device checks remain.
