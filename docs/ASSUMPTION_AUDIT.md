## Remaining verification and decisions

- **Child-process polling (#65):** Retained deliberately. The qdbus loop checks every 10 ms only during a call, for at most one second, draining both nonblocking pipes with a 1 MiB limit per stream; failure kills and waits for the child. Pipe readiness alone does not report exit if the child closes both pipes but keeps running. The UI checks every 25 ms only during the two-second graceful shutdown, then force-kills and waits; errors retain the process handle. `try_wait` reaps exited children. Neither interval is an idle background timer. Linux pidfds could provide exit readiness but need kernel support and a fallback; introducing that complexity for these short-lived paths is not justified without hardware measurements. Existing and added tests cover output draining, output limits, closed pipes, timeout, graceful exit and forced shutdown; deadlines are subject to OS scheduling. Measure real-device impact before claiming a battery improvement.
- The admission unit test covers concurrent saturation without binding sockets. End-to-end socket saturation, interrupted handshakes and held-key release remain to be verified in Linux CI and on Deck.
- Device checks for stock SteamOS, custom and reordered keyboard layouts, Gaming Mode detection and focus, installed artifacts and actual power impact remain open; no hardware result is inferred from CI.
